# MeeDoo 可靠性修复与发布验证

本次基于 feature/weekly-work-report，包含之前的看板预计算和排行榜暂时隐藏。2026-09-14 用户明确授权：测试通过后发布正式服。

## 修复项

1. Analytics 改为按最久尝试时间轮换，覆盖没有 request_id 的历史视频，使用原生 platform_post_id。每轮最多 80 条，Analytics 阶段最多 3 分钟，读取外部 API 最多等待 20 秒。失败也推进尝试时间，避免坏记录占住队列；大账号会跨多轮轮换，而不是永远只取 UUID 最小的前 50 条。
2. 重试通过数据库条件更新原子领取任务，清除旧平台 job ID，及时将父视频设为处理中，暂停媒体删除计划。新任务按 publications.request_id 查询；状态更新只匹配当前请求。网络或服务端错误属于结果未知，进入 reconciling，禁止直接再次发布；定时轮询及历史记录对账会继续确认。
3. Webhook 去重记录、平台更新、父视频状态和通知入队置于同一事务。失败返回 503 且不留下成功标记；重投可以重新处理。回调必须匹配当前平台 job，旧任务不能修改新任务。父视频状态按全部平台合并，避免单个平台成功就把整个视频标为成功。
4. 通知先持久化入库，不再同步等待 Lark。响应后及定时同步处理队列；外部调用有 8 秒超时，tenant token 在有效期内复用，HTTP 200 但业务 code 失败也会重试。旧通知默认不入新队列，避免上线后补发历史消息。队列使用行锁避免并行投递同一条消息，附带稳定请求标识；进程在发送后、记录前崩溃仍有外部系统去重期限所限制的重复风险，不宣称严格 exactly-once。
5. 整轮同步使用数据库 advisory lock，跨进程互斥。重复触发返回 alreadyRunning。
6. 历史 UUID 使用完整 seed 的 SHA-256，而不是截前 16 字节。已有 request_id / external_id / publication request 匹配到旧记录时沿用旧 ID，不批量改历史 ID。
7. 登录返回地址使用 URL 解析并校验同源，拒绝反斜杠与控制字符。前后端共用规则。
8. 用户随后要求长期保存视频：已提交视频不再自动删除，取消发布后 3 天、驳回/撤回后 7 天以及待审批 60 天的自动过期处理。现有删除期限清空。临时上传清理排除任何被 uploads 记录引用的文件；临时文件删除失败仍保留路径和记录，跳过该文件继续同步。
9. 看板与核算请求增加版本校验，旧响应和旧错误不会覆盖新选择；上传日期筛选与显示统一新加坡时区，明确累计视频指标与期间新增指标不同。
10. CSV 每 500 行批量写入；保留文件哈希、行级重复和重叠记录处理。649 元 / 16,300 积分公式不变。
11. README 更新为 96 小时、历史最高粉丝数正增量、零播放增量不分配的实际口径。没有实现或启用暂停中的 Google OAuth 项目。

- 并发重试：两次请求仅一次发布调用，其余返回 409。
- 旧状态隔离、未知结果进入确认流程、新 request_id 轮询。
- Webhook 故障回滚、重新投递、重复投递幂等。

## 运行边界

当平台永久不承认某个超时请求时，需要人工在平台核对后处理；系统不会为了恢复重试按钮而冒险重复发布。大规模视频数据按轮次更新，不承诺所有记录在每 15 分钟周期全部刷新。用户点击同步与定时任务遵守同一个锁。

测试/正式服此前已存在但未进入仓库的标题处理、媒体检查、里程碑与页面改动，已保留并整理回开发分支，避免下次从 Git 构建时丢失。环境文件和凭据不进入仓库。

API 依据：[Upload-Post Analytics 官方文档](https://docs.upload-post.com/api/get-analytics/)。


## 最终发布结果

测试服最终备份：`/opt/meedoo/.deploy-backups/reliability-test-20260914T051812Z`。
正式服备份：`/opt/meedoo/.deploy-backups/reliability-production-20260914T051859Z`（包含数据库备份、原构建与本次涉及的原文件）。两环境服务和同步定时任务均 active。

正式服默认 30 天接口，同一服务器本机 HTTP 连续三次：

| 版本 | 第一次 | 第二次 | 第三次 | 平均 |
| --- | ---: | ---: | ---: | ---: |
| 原版 | 12,607 ms | 12,175 ms | 11,655 ms | 12,145.7 ms |
| 新版预计算命中 | 131 ms | 28 ms | 22 ms | 60.3 ms |

每次平均减少 **12.085 秒，99.50%**；100 次约减少 **20 分 9 秒**等待。此为服务端本机接口获取及 JSON 解析耗时，不包括终端网络、浏览器下载及绘制时间，不能视为完整页面可交互时间。

正式核算数据仍为 13,494 积分、成本 537.2764417 元、批准视频 10 条、两位成员各 5 条。排行榜在发布构建中关闭；用户刷新页面后生效。


## 后续要求：视频长期保存

根据用户在正式发布后的追加要求，已提交视频改为长期保存，包括待审批、驳回、撤回与已发布的视频。不会按历史删除计划自动清理；未提交的临时会话和分块仍按过期策略处理。删除失败的临时文件会保留记录等待重试。已经删除的历史文件不由本次修改恢复。

隔离回归增加：过期的旧视频删除计划不会导致已提交文件消失；处于 failed 状态但被视频记录引用的过期 upload session 不会被清理。无实际媒体被测试删除。
